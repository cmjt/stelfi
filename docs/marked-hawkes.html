3.1 The model and your data

In the univariate Hawkes process (Chapter 2) every event triggers further events in exactly the same way. Often, though, some events are more “important” than others: a large earthquake triggers more aftershocks than a small one, and a tweet from an account with many followers is retweeted more than one from an account with few. If each event has a numeric value (a mark) that describes its importance, a marked Hawkes process lets the size of the jump in intensity after an event depend on that mark. In stelfi the conditional intensity is

\[\lambda(t) = \mu + \alpha \sum_{i:\tau_i<t}m(\tau_i)\,\text{exp}(-\beta (t-\tau_i)), \tag{3.1}\]

where \(m(\tau_i)\) is the mark of the event at time \(\tau_i\). The only difference to Equation 2.1 is that the jump after event \(i\) is \(\alpha m(\tau_i)\) rather than \(\alpha\), so an event with mark 2 has twice the effect of an event with mark 1. The parameters \(\mu\), \(\alpha\), and \(\beta\) are interpreted as in Chapter 2, except that the expected number of events triggered by an event with mark \(m\) is \(\alpha m / \beta\), and the average branching ratio is \(\alpha \bar{m} / \beta\), where \(\bar{m}\) is the average mark. stelfi constrains the average branching ratio to be less than 1.

3.1.1 What your data need to look like

You need two numeric vectors of the same length: the event times (exactly as in Section 2.1.1, sorted with no ties) and the marks, where marks[i] belongs to times[i]. In addition:

  • Marks must be non-negative, and an event with a mark of 0 triggers nothing.
  • The scale of the marks matters. Because the mark multiplies the jump, doubling all of the marks halves \(\alpha\), and adding a constant to all of the marks changes the model. You will usually want to transform your raw measurement into a mark that is proportional to how much you believe an event triggers. For example, in seismology the number of aftershocks is believed to grow exponentially with magnitude, so \(\text{exp}(\text{magnitude} - c)\) is a more natural mark than the magnitude itself (see Section 3.3). Different transformations can be compared using the likelihood (e.g., AIC).
  • The marks are treated as known. The model describes how marks affect future events but does not model the marks themselves (e.g., it does not predict the magnitude of the next earthquake). Missing marks need to be dealt with before fitting.
  • Marks only affect triggering, not the background. If the marks are also related to the background rate (e.g., larger events are rarer) this is not captured.

3.2 A simulated example

Data were simulated (using emhawkes, Lee (2023)) from a marked Hawkes process with \(\mu = 0.5\), \(\alpha = 0.3\), and \(\beta = 1.5\), where each event’s mark is equally likely to be 1, 2, 3, or 4. So an event with mark 4 increases the intensity by \(4 \times 0.3 = 1.2\), whereas an event with mark 1 increases it by only \(0.3\). In emhawkes the marks are generated by the function rmark, and the extra jump in the intensity caused by an event’s mark is given by the function impact: here \(0.3 \times (\text{mark} - 1)\), so that the total jump is \(0.3 \times \text{mark}\).

library(emhawkes)
fn_mark <- function(...) sample(1:4, 1) ## each mark is equally likely to be 1, 2, 3, or 4
impact <- function(param = c(eta1 = 0.3), alpha, n, mark, ...) {
    matrix(param["eta1"] * (mark[n] - 1), nrow = 1)
}
h_sim <- new("hspec", mu = 0.5, alpha = 0.3, beta = 1.5, rmark = fn_mark, impact = impact)
set.seed(1)
res <- hsim(h_sim, size = 1000, lambda_component0 = matrix(0.5))
## drop the dummy event at t = 0 that emhawkes adds
sim <- data.frame(times = res$arrival[-1], marks = res$mark[-1])

The data are a data frame of 999 event times and the corresponding marks:

3.2.2 Comparison with emhawkes

emhawkes can fit marked Hawkes processes where the effect of the mark is specified through an impact function. Here the jump after an event with mark \(m\) is \(\alpha + \eta (m - 1)\), which is a little more general than the stelfi model (the two are the same when \(\eta = \alpha\)), so emhawkes estimates one extra parameter, \(\eta\).

impact <- function(param = c(eta1 = 0.2), alpha, n, mark, ...) {
    matrix(param["eta1"] * (mark[n] - 1), nrow = 1)
}
h <- new("hspec", mu = 0.5, alpha = 0.2, beta = 1, impact = impact)
fit_em <- hfit(h, inter_arrival = res$inter_arrival, mark = res$mark,
               lambda_component0 = matrix(0.5))
em <- summary(fit_em)$estimate

3.3.1 Preparing the data

The times are converted to days since the first earthquake. The times are recorded to the nearest minute and some earthquakes share the same minute, so a small random amount of time (up to one minute) is added to each one. This keeps every earthquake, which is preferable to dropping tied events (Section 2.1.1). The data are then sorted by time, keeping each magnitude with its time.

eq <- data.frame(time = nz_earthquakes$origintime, magnitude = nz_earthquakes$magnitude)
eq$days <- as.numeric(difftime(eq$time, min(eq$time), units = "days"))
sum(duplicated(eq$days)) ## number of tied times
[1] 185
set.seed(1)
eq$days <- eq$days + runif(nrow(eq), 0, 1 / (24 * 60)) ## jitter by up to one minute
eq <- eq[order(eq$days), ]
eq$days <- eq$days - eq$days[1] ## start at t = 0

The catalogue only includes earthquakes of magnitude 3 and above. Seismologists usually assume that the number of aftershocks triggered by an earthquake grows exponentially with magnitude, so the mark is taken to be \(m = \text{exp}(\text{magnitude} - 3)\): an earthquake of magnitude 3 has mark 1, and one of magnitude 7.1 has mark \(e^{4.1} \approx 60\).

eq$mark <- exp(eq$magnitude - 3)
summary(eq$mark)

  1.000   1.150   1.397   1.781   1.916  66.686

3.3.2 Fitting the model

For comparison, both an unmarked model (every earthquake triggers equally) and the marked model are fitted.

sv <- c(mu = 0.3, alpha = 1, beta = 2)
fit_unmarked <- fit_hawkes(times = eq$days, parameters = sv)
fit_marked <- fit_hawkes(times = eq$days, parameters = sv, marks = eq$mark)
get_coefs(fit_unmarked)

get_coefs(fit_marked)
       Estimate Std. Error

The two models can be compared using AIC (twice the negative log-likelihood, stored as fit$objective, plus twice the number of parameters). Since the marks are treated as known, both models have three parameters.

c(unmarked = 2 * fit_unmarked$objective + 2 * 3,
  marked = 2 * fit_marked$objective + 2 * 3)
 unmarked    marked 
-12882.68 -13315.46

The marked model has a much lower AIC, so allowing larger earthquakes to trigger more aftershocks gives a substantially better description of the data. From the marked model:

Code 
pars <- get_coefs(fit_marked)[, 1]
  • background earthquakes occur at around 0.32 per day, i.e., about 571 of the 3824 earthquakes were not triggered by an earlier earthquake;
  • a magnitude 3 earthquake (mark 1) directly triggers on average \(\hat{\alpha}/\hat{\beta} =\) 0.48 further earthquakes, whereas a magnitude 5 earthquake (mark \(e^2 \approx 7.4\)) triggers around 3.5; and
  • the influence of an earthquake decays with a time scale of \(1/\hat{\beta} =\) 7.5 hours.

The fitted intensity shows the huge spikes in activity following the largest earthquakes.

show_hawkes(fit_marked, type = "both")

3.4 Goodness-of-fit

The goodness-of-fit procedures for the marked model are exactly those described in Section 2.4: the compensator now includes the marks, but show_hawkes_GOF() takes care of this. For the simulated example (where the model is correct) there is no evidence of lack of fit:

show_hawkes_GOF(fit)

data:  interarrivals

For both models the tests give very small p-values, and the plots show where the models fall short. Before the first large earthquake (around day 230) the compensator lies above the observed number of earthquakes, so the background rate is overestimated in this quiet period, while after each large earthquake the compensator lags below the observed count, so the models underpredict the number of aftershocks. The cluster of points in the bottom left corner of the consecutive compensator differences plot shows that short gaps tend to be followed by short gaps, which is the correlation picked up by the Ljung-Box test. Including the magnitudes improves the likelihood considerably (see the AIC above), but the diagnostic plots for the two models look similar, and neither model is fully adequate.

This is a well known feature of earthquake data: aftershock activity decays like a power law in time (the Omori-Utsu law) rather than exponentially, so an exponential kernel cannot capture both the very intense activity immediately after a large earthquake and the long tail of aftershocks that follows. Models designed specifically for earthquakes (e.g., the ETAS model) use a power law kernel. The background rate is also unlikely to be constant over the whole period. The marked Hawkes model is still useful, for example for quantifying how much more a large earthquake triggers than a small one, but its estimates should be interpreted with these limitations in mind.
