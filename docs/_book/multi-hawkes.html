4  Multivariate Hawkes process

4.1 The model and your data

Often events come in different types, or streams, and events of one type can trigger events of another. For example, large earthquakes trigger small ones, attacks by one group might provoke attacks by another, and buy orders on a stock exchange can trigger sell orders. A multivariate Hawkes process extends the univariate Hawkes process (Chapter 2) so that each stream has its own intensity, and every event can increase the intensity of every stream. In stelfi the conditional intensity of stream \(j\) (\(j = 1, ..., N\)) is

\[\lambda_j(t) = \mu_j + \sum_{k = 1}^N \alpha_{jk} \sum_{i:\tau_i<t,\ s_i = k} \text{exp}(-\beta_k (t-\tau_i)), \tag{4.1}\]

where \(s_i\) is the stream of the event at time \(\tau_i\). The parameters are

  • \(\mu_j\), the background rate of stream \(j\);
  • \(\alpha_{jk}\), the jump in the intensity of stream \(j\) caused by an event in stream \(k\). These form an \(N \times N\) matrix \(\boldsymbol{\alpha}\): the diagonal elements (\(\alpha_{jj}\)) describe self-excitation (events triggering events of the same type) and the off-diagonal elements describe cross-excitation (events of one type triggering events of another type); and
  • \(\beta_k\), the rate at which the excitement caused by an event in stream \(k\) decays. Note that in stelfi the decay rate belongs to the stream that caused the excitement.

The expected number of stream \(j\) events directly triggered by a single stream \(k\) event is \(\alpha_{jk}/\beta_k\). stelfi constrains each of these to be at most 1 (i.e., \(\alpha_{jk} \leq \beta_k\)).

Plotted below are the conditional intensities of a bivariate (two stream) Hawkes process with \(\boldsymbol{\mu} = (0.5, 0.9)\), \(\boldsymbol{\alpha}\) = \(\begin{bmatrix}0.2&0.1 \\0.6&0.5 \\\end{bmatrix}\), and \(\boldsymbol{\beta} = (0.8, 0.8)\). Events are shown by the vertical dashes along the x-axis. An event in either stream increases the intensity of both streams, but an event in stream 1 has a much bigger effect on stream 2 (\(\alpha_{21} = 0.6\)) than an event in stream 2 has on stream 1 (\(\alpha_{12} = 0.1\)).

4.1.1 What your data need to look like

fit_mhawkes() needs two vectors of the same length:

  • times, the event times of all streams combined, sorted in ascending order with no ties (see Section 2.1.1; ties between streams are not allowed either); and
  • stream, a character vector giving the stream of each event, so stream[i] is the type of the event at times[i].

In addition:

  • Streams are ordered alphabetically. Parameters for “stream 1” refer to the first stream name in alphabetical order. Choose stream names so that this order is the one you want (e.g., "A_small" and "B_large").
  • The number of parameters grows quickly. With \(N\) streams there are \(N + N^2 + N\) parameters (8 for two streams, 15 for three). Each stream needs a reasonable number of events, and in particular there need to be enough events in each stream to estimate the cross-excitation parameters. Two or three streams is usually plenty.
  • Every event must belong to exactly one stream. If your event types overlap, or the type is unknown for some events, these need to be dealt with before fitting.
  • The limitations of the univariate model apply to each stream: constant background rates, exponential decay, and an observation period from \(0\) to the last event.

4.2 A simulated example

Data were simulated (using the hawkes package, Zaatour (2014)) from a bivariate Hawkes process with the parameters given above over the time period \(t \in [0, 500]\). The decay rates of the two streams are equal (\(\beta_1 = \beta_2 = 0.8\)), because the hawkes package attaches the decay rate to the stream being excited rather than to the stream causing the excitement (as stelfi does); with equal decay rates the two formulations are the same model. 4.2.1 Fitting the model using stelfi

The model is fitted using fit_mhawkes() with the times, the stream of each event, and a list of starting values: a vector mu, a matrix alpha, and a vector beta. Because there are many parameters it is a good idea to ask the optimiser (optim()) to use the "BFGS" method, which uses the gradient that TMB calculates, rather than the default (Nelder-Mead), which can stop before reaching the maximum.

sv <- list(mu = c(0.5, 0.5),
           alpha = matrix(c(0.3, 0.3, 0.3, 0.3), nrow = 2),
           beta = c(1, 1))
fit <- fit_mhawkes(times = data$times, stream = data$stream, parameters = sv,
                   method = "BFGS")
stelfi <- get_coefs(fit)

4.2.2 Comparison with the hawkes package

The hawkes package (Zaatour (2014)) does not have a fitting function, but it does provide the negative log-likelihood (likelihoodHawkes()), which can be minimised using optim(). The parameters are estimated on the log scale (to keep them positive) and the standard errors are obtained from the Hessian using the delta method.

nll <- function(p) {
    hawkes::likelihoodHawkes(lambda0 = exp(p[1:2]),
                             alpha = matrix(exp(p[3:6]), nrow = 2, byrow = TRUE),
                             beta = exp(p[7:8]), history = sim)
}
start <- log(c(0.5, 0.5, 0.3, 0.3, 0.3, 0.3, 1, 1))
opt <- optim(start, nll, method = "BFGS", hessian = TRUE)
est <- exp(opt$par)
se <- est * sqrt(diag(solve(opt$hessian))) ## delta method
## order: mu_1, mu_2, alpha_11, alpha_12, alpha_21, alpha_22, beta_1, beta_2
hk <- cbind(Estimate = est, "Std. Error" = se)

stelfi 0.686 (0.11) 1.051 (0.207) 0.133 (0.066) 0.579 (0.167) 0.107 (0.024) 0.597 (0.078) 0.898 (0.374) 0.972 (0.149)

The two approaches give very similar estimates, and both recover the true values well. In particular both correctly identify that events in stream 1 strongly excite stream 2 (\(\alpha_{21}\)) but not the other way around (\(\alpha_{12}\)).

4.2.3 Plotting the fitted model

The data can be plotted using show_multivariate_hawkes() with type = "data". The fitted intensities are calculated below using a short helper function that evaluates Equation 4.1 at a grid of times (the same function is used for the goodness-of-fit checks in Section 4.4).

show_multivariate_hawkes(fit, type = "data")
## estimated parameters as a vector mu, a matrix alpha, and a vector beta
mhawkes_pars <- function(fit) {
    cf <- get_coefs(fit)[, 1]
    N <- length(table(fit$env$data$stream))
    list(mu = cf[1:N],
         alpha = matrix(cf[(N + 1):(N + N^2)], nrow = N), ## column-major order
         beta = cf[(N + N^2 + 1):(2 * N + N^2)])
}
## conditional intensity of each stream at times p
mhawkes_intensity <- function(times, stream, pars, p) {
    s <- as.integer(factor(stream))
    sapply(seq_along(pars$mu), function(j) {
        sapply(p, function(t) {
            prev <- times < t
            pars$mu[j] + sum(pars$alpha[j, s[prev]] *
                             exp(-pars$beta[s[prev]] * (t - times[prev])))
        })
    })
}
pars <- mhawkes_pars(fit)
p <- seq(0, 50, length.out = 1000) ## the first 50 time units only
lam <- mhawkes_intensity(data$times, data$stream, pars, p)
plot_data <- data.frame(t = rep(p, 2), intensity = as.vector(lam),
                        stream = rep(sort(unique(data$stream)), each = length(p)))
ggplot(plot_data, aes(x = t, y = intensity, col = stream)) +
    geom_line() + theme_minimal() + xlab("Time") + ylab(expression(lambda[j](t)))

4.3 An applied example: large and small earthquakes

In Section 3.3 the magnitude of each Canterbury earthquake was used as a mark. An alternative is to split the earthquakes into two streams, small (magnitude 3 to 4) and large (magnitude 4 and above), and ask how much each type triggers the other. The data are prepared exactly as before (times in days, jittered to remove ties).

data(nz_earthquakes, package = "stelfi")
eq <- data.frame(time = nz_earthquakes$origintime, magnitude = nz_earthquakes$magnitude)
eq$days <- as.numeric(difftime(eq$time, min(eq$time), units = "days"))
set.seed(1)
eq$days <- eq$days + runif(nrow(eq), 0, 1 / (24 * 60))
eq <- eq[order(eq$days), ]
eq$days <- eq$days - eq$days[1]
## streams (alphabetical order: "M3-4" is stream 1, "M4+" is stream 2)
eq$size <- ifelse(eq$magnitude >= 4, "M4+", "M3-4")
table(eq$size)

M3-4  M4+ 
3445  379 
sv <- list(mu = c(0.3, 0.05),
           alpha = matrix(c(1, 0.5, 0.5, 0.5), nrow = 2),
           beta = c(2, 2))
fit_eq <- fit_mhawkes(times = eq$days, stream = eq$size, parameters = sv, method = "BFGS")
pars_eq <- get_coefs(fit_eq)

Here stream 1 is small earthquakes and stream 2 is large earthquakes. It is easiest to interpret the estimates as the expected number of events of each type directly triggered by one event, \(\alpha_{jk}/\beta_k\):

pe <- mhawkes_pars(fit_eq)
branching <- sweep(pe$alpha, 2, pe$beta, "/") ## alpha_jk / beta_k
dimnames(branching) <- list(triggered = c("small", "large"), trigger = c("small", "large"))
round(branching, 3)
         trigger
triggered small large
    small 0.782 1.000
    large 0.041 0.505
  • A small earthquake triggers on average 0.78 further small earthquakes and only 0.041 large ones.
  • A large earthquake triggers on average 1 small earthquakes and 0.51 large ones.
  • The excitement caused by a large earthquake decays very quickly (\(1/\hat{\beta}_2 =\) 23 minutes) compared to that caused by a small earthquake (\(1/\hat{\beta}_1 =\) 18.7 hours).

Notice that the estimate of \(\alpha_{12}/\beta_2\) (small earthquakes triggered by a large one) is 1, the maximum allowed by stelfi. In reality large earthquakes trigger many more than one aftershock each, so this constraint is limiting the model here, and the estimate should be read as “at least one”. The marked model (Section 3.3), where the effect of an earthquake grows continuously with its magnitude, does not have this limitation, and is probably a more natural model for these data.

4.4 Goodness-of-fit

The ideas of Section 2.4 apply to each stream separately: if the model is correct then, for each stream \(j\), the compensator \(\Lambda_j(t) = \int_0^t \lambda_j(s) ds\) evaluated at the times of the stream \(j\) events transforms them into a unit rate Poisson process, so the differences between consecutive values should be \(\text{Exp}(1)\). Note that \(\lambda_j(t)\) depends on the events in all streams. For Equation 4.1 the compensator is

\[\Lambda_j(t) = \mu_j t + \sum_{k=1}^N \frac{\alpha_{jk}}{\beta_k} \sum_{i:\tau_i < t,\ s_i = k} \left(1 - \text{exp}(-\beta_k (t - \tau_i))\right).\]

show_hawkes_GOF() does not (yet) work for multivariate models, but the compensator differences are easily calculated with the function below, and the tests from Section 2.4 applied to each stream.

mhawkes_compensator_differences <- function(fit) {
    times <- fit$env$data$times
    stream <- fit$env$data$stream
    pars <- mhawkes_pars(fit)
    s <- as.integer(factor(stream))
    out <- lapply(seq_along(pars$mu), function(j) {
        comp <- sapply(times[s == j], function(t) {
            prev <- times < t
            pars$mu[j] * t + sum(pars$alpha[j, s[prev]] / pars$beta[s[prev]] *
                                 (1 - exp(-pars$beta[s[prev]] * (t - times[prev]))))
        })
        diff(c(0, comp))
    })
    names(out) <- sort(unique(stream))
    out
}

For the simulated example (where the model is correct) there is no evidence of lack of fit in either stream:

cd <- mhawkes_compensator_differences(fit)

QQ plots of the compensator differences for each stream against the \(\text{Exp}(1)\) distribution show where the problems lie.

qq <- do.call(rbind, lapply(names(cd_eq), function(nm) {
    pp <- ppoints(200)
    data.frame(stream = nm, theoretical = qexp(pp), observed = quantile(cd_eq[[nm]], pp))
}))
ggplot(qq, aes(x = theoretical, y = observed)) +
    geom_point() + geom_abline(intercept = 0, slope = 1, col = "red") +
    facet_wrap(~stream, scales = "free") + theme_minimal() +
    xlab("Theoretical quantiles, Exp(1)") + ylab("Observed quantiles")

As for the univariate and marked models (Section 3.4), the tests reject the model for these data. The reasons are the same: the exponential decay of the excitement is too simple to describe aftershock sequences, and (as discussed above) the constraint on \(\alpha_{12}\) prevents the model from allowing a large earthquake to trigger many small ones.
