8.1 The model and your data

A spatiotemporal self-exciting model combines ideas from the Hawkes process (Chapter 2) and the LGCP (Chapter 6). Events have a time and a location, and each event temporarily increases the chance of further events nearby, in both time and space. Earthquake aftershocks, the spread of crime (“near repeat” burglaries), and outbreaks of disease are typical examples. The intensity used by stelfi (see Reinhart (2018)) is

\[\lambda(s,t) = \mu + \alpha \sum_{i:\tau_i<t} \text{exp}(-\beta (t-\tau_i))\, f(s - x_i), \tag{8.1}\]

where \(\tau_i\) and \(x_i\) are the time and location of event \(i\), and

  • \(\mu\) is the background rate, the expected number of spontaneous events per unit area per unit time;
  • \(\alpha\) and \(\beta\) describe the temporal self-excitement, exactly as for a Hawkes process: each event triggers on average \(\alpha/\beta\) further events (if all of its spatial influence falls within the study region), and its influence decays with time scale \(1/\beta\); and
  • \(f(\cdot)\) is the spatial triggering kernel, a bivariate normal density centred on the triggering event with standard deviations \(\sigma_x\) and \(\sigma_y\) (in the x and y directions) and correlation \(\rho\). So triggered events tend to occur within a couple of standard deviations of the event that triggered them, and \(\rho \neq 0\) means triggering is stronger along one diagonal direction than the other.

Two extensions are available:

  • A spatially varying background. Setting GMRF = TRUE replaces \(\mu\) with \(\mu(s) = \text{exp}(\beta_0 + G(s))\), where \(G(s)\) is a Gaussian random field as in an LGCP. Spatial covariates can also be included in the background via the covariates argument (one row per mesh node). This is important if some areas simply have more events than others, as otherwise this will be mistaken for self-excitement.
  • A spreading kernel. Setting time_independent = FALSE makes the spread of the kernel grow with time since the triggering event (its covariance is proportional to \(t - \tau_i\)), appropriate when the triggering mechanism travels at a finite speed. This is very memory intensive.

get_coefs() reports mu and coefs (the log of the background rate, followed by any covariate coefficients), alpha, beta, xsigma, ysigma, rho, and, with GMRF = TRUE, the field parameters kappa and tau.

8.1.1 What your data need to look like

fit_stelfi() needs

  • times, a numeric vector of event times, sorted with no ties (exactly as for a Hawkes process, Section 2.1.1);
  • locs, a data frame with columns x and y giving the location of each event, in the same order as times;
  • sf, an sf polygon of the study region; and
  • smesh, a mesh of the study region (Chapter 5).

Things to be aware of:

  • Use projected coordinates in sensible units (e.g., km), as for an LGCP (Section 6.1.1). The units of time and distance set the units of the parameters: \(\mu\) is then events per km\(^2\) per day (say) and \(\sigma_x\), \(\sigma_y\) are in km.
  • The mesh is used to integrate the intensity over the study region, both the background and the spatial kernel of every event. The mesh therefore needs to be fine relative to the spread of the kernel (\(\sigma_x\), \(\sigma_y\)) where there are events, otherwise the integral of the kernel is inaccurate and so are the estimates. A good approach is to build the mesh around the events (loc = locs) with a small cutoff, which gives small triangles where events are and larger ones elsewhere. fit_stelfi() gives a warning if the mesh looks too coarse for the estimated kernel, and the accuracy can be checked in more detail after fitting (Section 8.4).
  • Edge effects. Events near the edge of the study region trigger events that may fall outside it, and are therefore unobserved. The model accounts for this (the integral of the kernel only covers the study region), but the study region should be the region where events could have been observed.
  • Computation. The likelihood involves every pair of events, so the cost grows with the square of the number of events. A few hundred to a few thousand events is feasible; for more, consider a subset (e.g., a time window or the larger events).
  • Starting values. parameters is a list with coefs (the log of the background rate, or alternatively mu, the background rate itself; if neither is given a crude default is used), alpha, beta, xsigma, ysigma, rho, and, with GMRF = TRUE, kappa and tau. Choose xsigma and ysigma to be roughly the distance over which you expect triggering to occur, and \(\alpha < \beta\). The model can be sensitive to starting values, particularly with GMRF = TRUE, so it is worth trying a few.

8.2 A simulated example

Data were simulated from Equation 8.1 within the (elliptical) study region of the xyt dataset (see Chapter 10), with background rate \(\mu = 1\), \(\alpha = 2\) and \(\beta = 4\) (so each event triggers on average \(2/4 = 0.5\) events), and a kernel with \(\sigma_x = 0.5\), \(\sigma_y = 0.25\) and \(\rho = 0\) (so triggering spreads twice as far in the x direction as in the y direction).

stelfi does not have a separate simulation function for this model. Instead, the fitted model object returned by fit_stelfi() has a simulate() method that simulates a new point pattern, over the same study region and time period, from the model with any given parameter values. So below the model is first fitted to the xyt data (the estimates themselves are not used), and the simulate() method is then called with the true parameter values. These must be given on the scale used internally by stelfi: the log of \(\mu\) (coefs), the logit of \(\alpha/\beta\), the logs of \(\beta\), \(\sigma_x\) and \(\sigma_y\), and \(\text{atanh}(\rho)\).

data(xyt, package = "stelfi")
domain <- sf::st_as_sf(xyt$window)
bnd <- fmesher::fm_as_segm(as.matrix(sf::st_coordinates(domain)[, 1:2]))
smesh <- fmesher::fm_mesh_2d(boundary = bnd, max.edge = 0.75, cutoff = 0.3)
fit0 <- fit_stelfi(times = xyt$t, locs = data.frame(x = xyt$x, y = xyt$y), sf = domain,
                   smesh = smesh, parameters = list(alpha = 1, beta = 3, xsigma = 0.3,
                                                    ysigma = 0.3, rho = 0))
truth <- c(mu = 1, alpha = 2, beta = 4, xsigma = 0.5, ysigma = 0.25, rho = 0)
set.seed(2)
sim <- fit0$simulate(par = c(coefs = log(1), logit_abratio = qlogis(2 / 4), log_beta = log(4),
                             log_xsigma = log(0.5), log_ysigma = log(0.25), atanh_rho = 0))
## sort the events by time
ord <- order(sim$times)
locs <- data.frame(x = sim$locs[ord, 1], y = sim$locs[ord, 2])
times <- sim$times[ord]

8.2.1 Fitting the model using stelfi

The study region is an sf polygon (here taken from the xyt data) and the mesh follows its boundary. These are the same as those used to simulate the data, but are repeated below so that the code needed to fit the model is all in one place.

domain <- sf::st_as_sf(xyt$window)
bnd <- fmesher::fm_as_segm(as.matrix(sf::st_coordinates(domain)[, 1:2]))
smesh <- fmesher::fm_mesh_2d(boundary = bnd, max.edge = 0.75, cutoff = 0.3)
area <- as.numeric(sf::st_area(domain))
param <- list(coefs = log(length(times) / (area * max(times))), ## log events per area per time
              alpha = 1, beta = 3, xsigma = 0.3, ysigma = 0.3, rho = 0)
fit <- fit_stelfi(times = times, locs = locs, sf = domain, smesh = smesh, parameters = param)
stelfi <- get_coefs(fit)

plot_kernel <- function(pars, lim = 2) {

                      rep(pars["rho", 1] * pars["xsigma", 1] * pars["ysigma", 1], 2),

8.3 An applied example: Canterbury earthquakes

The Canterbury earthquakes were modelled in time only in Section 3.3 and Section 4.3. Here their locations are included. To keep computation manageable, only the 379 earthquakes of magnitude 4 and above are used.

8.3.1 Preparing the data

The earthquakes are projected to New Zealand Transverse Mercator (EPSG:2193) and converted to km. Times are in days since the first earthquake, jittered to remove ties (Section 3.3), and the data are sorted by time.

data(nz_earthquakes, package = "stelfi")
eq <- nz_earthquakes[nz_earthquakes$magnitude >= 4, ]
xy <- sf::st_coordinates(sf::st_transform(eq, crs = 2193)) / 1000
set.seed(1)
days <- as.numeric(difftime(eq$origintime, min(eq$origintime), units = "days")) +
    runif(nrow(eq), 0, 1 / (24 * 60))
ord <- order(days)
times <- days[ord] - min(days)
locs <- data.frame(x = xy[ord, 1], y = xy[ord, 2])

The catalogue does not come with a study region, so here the region is taken to be the convex hull of the earthquakes, extended by 20 km. In your own application the study region should reflect where events could have been recorded.

domain <- sf::st_as_sf(locs, coords = c("x", "y")) |>
    sf::st_union() |>
    sf::st_convex_hull() |>
    sf::st_buffer(20)
domain <- sf::st_sf(geometry = domain)

The mesh is built around the earthquakes with a small cutoff (1 km), so that triangles are small where earthquakes are (much smaller than the few km over which aftershocks are expected) and larger elsewhere.

smesh <- fmesher::fm_mesh_2d(loc = locs, boundary = fmesher::fm_as_segm(domain),
                             max.edge = c(30, 100), cutoff = 1)

Two models are fitted: one with a constant background, and one with a spatially varying background (GMRF = TRUE). For the latter, starting values for the field are needed: here a range of about 40 km (\(\kappa = \sqrt{8}/40\)).

8.4 Goodness-of-fit

8.4.1 Checking the mesh

stelfi integrates the spatial kernel of each event over the study region using the mesh. For an event well inside the region the integral should be close to 1 (and less than 1 for an event near the edge). This can be checked by comparing the mesh-based integral with an accurate Monte Carlo estimate (the proportion of points simulated from the kernel that fall inside the study region).

kernel_volume <- function(pars, locs, sf, smesh, n_mc = 2000) {
    sigma <- matrix(c(pars["xsigma", 1]^2,
                      rep(pars["rho", 1] * pars["xsigma", 1] * pars["ysigma", 1], 2),
                      pars["ysigma", 1]^2), ncol = 2)
    w <- get_weights(smesh, sf)$weights
    window <- spatstat.geom::as.owin(sf)
    t(sapply(seq_len(nrow(locs)), function(i) {
        centre <- unlist(locs[i, c("x", "y")])
        mesh <- sum(w * mvtnorm::dmvnorm(smesh$loc[, 1:2], mean = centre, sigma = sigma))
        draws <- mvtnorm::rmvnorm(n_mc, mean = centre, sigma = sigma)
        mc <- mean(spatstat.geom::inside.owin(draws[, 1], draws[, 2], window))
        c(mesh = mesh, monte_carlo = mc)
    }))
}
set.seed(1)
vol <- kernel_volume(pars_eq, locs, domain, smesh)
summary(vol)

For 77% of the earthquakes the mesh-based integral is within 0.1 of the Monte Carlo value. Where they differ a lot (typically isolated earthquakes in parts of the region where the mesh is coarse) the mesh should be refined.

8.4.2 Checking the temporal pattern

Integrating Equation 8.1 over the study region gives the intensity of the event times, which is a marked Hawkes process (Chapter 3) with background rate \(\int \mu(s) ds\) (the background integrated over the region) and with the mark of each event being the integral of its kernel over the study region (the Monte Carlo values above). The goodness-of-fit checks of Section 2.4 can therefore be applied to the times, using show_hawkes_GOF() with a list containing the times, the parameters, and the marks.

w <- get_weights(smesh, domain)$weights
mu_total <- sum(w * exp(pars_eq["coefs", 1] + as.vector(get_fields(fit_eq_gmrf, smesh))))
temporal <- list(times = times, marks = vol[, "monte_carlo"],
                 params = c(mu = mu_total, alpha = pars_eq["alpha", 1], beta = pars_eq["beta", 1]))
show_hawkes_GOF(temporal)

As for the purely temporal models of the earthquakes (Section 3.4), the tests reject the model and the plots show the same features: the exponential decay in time cannot describe both the burst of activity immediately after a large earthquake and the long tail of aftershocks that follows, and every earthquake is assumed to trigger equally regardless of its magnitude. Adding space improves the description of where aftershocks occur, but does not fix these temporal limitations.
